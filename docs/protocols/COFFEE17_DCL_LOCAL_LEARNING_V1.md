# Coffee17 DCL-Style Local Learning V1

## Purpose

Test one hypothesis only: after the frozen-representation audit failed to support a global-representation explanation, can training-time local destruction/construction improve the persistent Coffee17 hard classes while keeping exactly the same HBP inference architecture?

This is a matched five-fold development experiment. The outer test remains untouched.

## Control and treatment

Both arms use the same:

- Coffee17 original 979-image source;
- five locked development folds, seed 42;
- raw RGB, 224x224;
- deterministic rotation schedule [0,45,90,135,180,225,270];
- MobileNetV3-Large ImageNet initialization;
- HBP head, out_indices [1,3,4], projection 512;
- linear 17-class classifier;
- dropout 0.2;
- AdamW, lr 3e-4, weight decay 1e-4;
- 50 epochs, cosine schedule;
- CE with label smoothing 0.1;
- best checkpoint selected by development Macro-F1.

Arms:

- `HBP_CE`: canonical raw-RGB HBP control.
- `HBP_DCL`: identical HBP inference core, plus training-only DCL-style objectives.

The treatment does not add parameters or branches at inference. The saved `inference_core` is the same model class as the control.

## DCL adaptation

The implementation follows the mechanism of Chen et al., CVPR 2019: classify both original and locally shuffled images, distinguish original vs shuffled images, and predict the original spatial placement of shuffled regions.

Coffee17 adaptation is preregistered as follows.

### Region Confusion Mechanism

Input 224x224 is partitioned into a 4x4 grid (56x56 pixel regions). The original DCL uses 7x7 on a 448 crop; V1 uses 4x4 to keep approximately similar patch scale.

The local RCM uses neighbor span 2: adjacent horizontal swaps are sampled inside each row, followed by adjacent row swaps. Every shuffled image is therefore a permutation of the same 16 regions; no pixels are synthesized.

The RCM RNG is derived deterministically from seed, epoch, batch index, and sample index and does not consume the global model RNG stream.

### Classification objective

Original and shuffled versions share the same MobileNetV3+HBP core. Both retain the same Coffee17 class label.

`L_cls = CE([z_original,z_shuffled], [y,y])`

### Original-vs-shuffled objective

A training-only linear head acts on the HBP embedding:

`L_swap = CE(swap_logits, original_or_shuffled)`

The labels follow the official DCL implementation convention: original=1, shuffled=0.

### Region alignment objective

A training-only 1x1 convolution acts on the final spatial feature map. Adaptive pooling produces a 4x4 location matrix. Each output cell regresses the normalized original patch index with L1 loss.

Unlike the historical DCL code, which infers the permutation through patch appearance matching, this implementation uses the exact known permutation generated by RCM. This removes avoidable target noise while preserving the construction task.

### Total treatment loss

`L = L_cls + L_swap + L_loc`

All three weights are fixed at 1.0 before training. V1 performs no validation tuning.

## Hard-class evaluation

Hard-F1 is the F1 mean over the union of the six preregistered hard pairs:

1. Withered vs Immature
2. Severe Insect Damage vs Slight Insect Damage
3. Cut vs Slight Insect Damage
4. Partial Sour vs Full Sour
5. Slight Insect Damage vs Fade
6. Full Black vs Partial Black

For every fold the experiment also records bidirectional confusion counts for these exact pairs and paired rescue/damage outcomes on identical validation rows.

## Decision gate

`SUPPORT_LOCAL_DCL` requires all six conditions:

1. mean Macro-F1 delta > 0;
2. Macro-F1 improves in at least 4/5 folds;
3. mean Hard-F1 delta > 0;
4. Hard-F1 improves in at least 4/5 folds;
5. total confusion across the six hard pairs decreases;
6. mean Worst-F1 delta is non-negative.

Otherwise the decision is `NO_CLEAR_DCL_SUPPORT`.

No hyperparameter rescue is allowed after observing V1. If V1 fails, the DCL-style route is not repeatedly tuned on these folds.

## Inference constraint

Only the MobileNetV3-Large + HBP + linear classifier core is used at validation/deployment. RCM, swap classifier, and region-alignment head are training-only.
